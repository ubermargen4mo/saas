# Изменения

## Вход в Google и ссылки из других приложений (не выпущено)
- **Вход в аккаунт (`Tab.kt`, `ExternalLinks.kt`):** переход по обычной ссылке `http(s)` считался нажатием пользователя и в цепочке редиректов (правило «жест не старше 15 с», добавленное для OAuth-возврата в приложения). Вход Google перекидывает между `accounts.google.com`, `youtube.com`, `mail.google.com`, и на таком переходе выскакивал вопрос «Открыть в приложении?» (или сразу открывалось YouTube/Gmail), а загрузка страницы при этом блокировалась: страница «оставалась как есть». Теперь для `http(s)` нужно настоящее нажатие и не редирект; для внешних схем (`intent://`, `com.app:/oauth`) правило с редиректом сохранено. Дополнительно страницы входа (`accounts.*`, `login.*`, `auth.*`, `sso.*`, пути `/signin`, `/login`, `/oauth`, `/authorize` и т.п.) никогда не уходят в приложения.
- **Режим сайта на странице входа (`Tab.kt`):** переход на `accounts.*` не переключает режим «версия для ПК» и не перезагружает страницу посреди входа.
- **Custom Tabs (`HripsCustomTabsService.kt`, `AndroidManifest.xml`, `build.gradle.kts`):** добавлен минимальный провайдер `android.support.customtabs.action.CustomTabsService` (`androidx.browser:browser:1.8.0`). Приложения вроде YouTube, Telegram, Gmail открывают ссылки во «встроенном браузере» через браузер по умолчанию, если он объявляет этот сервис; без него они брали Chrome или свой WebView. Для этого hrips должен быть браузером по умолчанию. Прогрев, предзагрузка, обмен сообщениями отвечают отказом. «Назад» возвращает в приложение-источник (`fromApp`, уже было).
- **Поиск из системы (`IncomingIntents.kt`, `AndroidManifest.xml`):** принимается `android.intent.action.WEB_SEARCH` (ассистенты, виджеты поиска).
- Не проверено сборкой: нужны два контрольных прогона на телефоне: вход в Google с подтверждением на устройстве; ссылка из описания YouTube при hrips по умолчанию.

## Стабильность: чёрный экран после сворачивания и выбора файла, тормоза (не выпущено)
- **Сборка (`Browser.kt`):** `newTab` объявлен как возвращающий `Tab`, но ничего не возвращал: исходники не компилировались (`MainActivity` берёт результат). Добавлен `return tab`.
- **Чёрная или прозрачная страница после возврата (`SurfaceGuard.kt`, `BrowserScreen.kt`, `Browser.kt`):** при каждом возврате приложения на экран (свёртывание, системный выбор файла) через 1 с снимается кадр страницы; если он пустой, не пришёл за 1,5 с или снять не удалось, у GeckoView запрашивается новая поверхность (`requestNewSurface`). Исправный экран не трогается. В logcat тег `HripsSurface`.
- **Активность страницы ведёт GeckoView (`Browser.kt`, `Tab.kt`):** при свёртывании и возврате приложение больше не вызывает `setActive`/`setFocused` у показанной вкладки: GeckoView сам делает это по жизни поверхности (`Display.acquire/release`, `maybeSetActive`), как в Firefox для Android (`GeckoEngineView` их не вызывает вообще). Прямой `setActive(false)` ещё и обходит защиту картинки в картинке. Для остальных вкладок и при смене вкладки всё как раньше.
- **Выбор файла (`UploadFiles.kt`, `MainActivity.kt`):** копии для загрузки больше не удаляются при каждом новом выборе (движок читает файл по пути во время отправки, а вторая загрузка стирала первую); чистятся копии старше 30 минут. Если копирование идёт дольше 0,7 с, показывается «Подготавливаю файлы…». Проверка APK обновления (`Updater.cleanup`) вынесена из главного потока: она шла в каждом `onStart`, в том числе после выбора файла.
- **Снимки вкладок (`TabSwitcher.kt`, `BrowserScreen.kt`):** автоматический снимок после загрузки страницы не чаще раза в 8 с на вкладку, не при полноэкранном режиме и не в свёрнутом приложении (каждый снимок это чтение кадра с GPU). Снимок при открытии переключателя и при смахивании не ограничен.
- **Выгрузка вкладок при нехватке памяти (`Browser.kt`):** событие `TRIM_MEMORY_UI_HIDDEN` (само свёртывание) попадало под «критическую» ветку и выгружало вкладки; теперь игнорируется. Работает только при включённой настройке.
- **Окно (`BrowserScreen.kt`):** `FLAG_SECURE` меняется только при реальной смене (каждая смена пересоздаёт поверхность окна).
- **Первый кадр (`themes.xml`, `colors.xml`):** фон окна задан цветом поверхности темы, а не системным чёрным; при холодном запуске после убийства процесса вместо чёрного экрана виден цвет приложения.
- **Скрипт предпросмотра (`hover/content.js`, версия 1.3):** слушатели касаний, указателя и прокрутки помечены `passive`, чтобы скрипт, работающий на каждой странице и во всех фреймах, не задерживал прокрутку.
- Не проверено сборкой и запуском: в рабочем окружении нет Android SDK и доступа к maven.mozilla.org. Если после сборки симптом остался, нужен `adb logcat` (теги `HripsSurface`, `HripsTab`, `Browser`, `AndroidRuntime`) в момент сбоя.

## Совместимость с сайтами: файлы, вход через Google, возврат в приложения (не выпущено)
- **Выбор файлов (`FilePicker.kt`, `MainActivity.kt`, `Prompts.kt`):** вместо `OpenDocument`/фото-пикера открывается системный chooser `ACTION_GET_CONTENT`, как в Chrome: «Файлы», галерея, Google Диск, мессенджеры и любые другие приложения-поставщики файлов. Если сайт принимает фото, видео или звук, в списке есть «Камера», «Видеокамера», «Запись звука» (камера только при выданном разрешении CAMERA, иначе система бросает SecurityException). Атрибут `capture` у `<input type=file>` сразу открывает камеру (`USER` - фронтальная). Снимок пишется в `cache/capture` через FileProvider (путь добавлен в `file_paths.xml`), дальше копируется как раньше (`UploadFiles`). Выбор папки не менялся.
- **Попапы входа (`Tab.kt`, `Browser.kt`):** добавлен `ContentDelegate.onCloseRequest`: `window.close()` из окна входа Google/OAuth/оплаты закрывает вкладку и возвращает к странице, которая её открыла (раньше окно оставалось висеть и сайт не получал результат входа). Попап теперь привязывается к вкладке, которая его открыла (`onNewWindow(opener, uri)`), а не к текущей.
- **Возврат в приложения после входа (`Tab.kt`):** переход на внешнюю схему (`intent://`, `com.app:/oauth`, `market:` и т.п.) через HTTP-редирект считается действием пользователя, если в этой вкладке был жест не больше 15 с назад (`REDIRECT_GESTURE_MS`). Раньше такие редиректы молча блокировались, и приложение не получало ответ OAuth. Переходы без жеста и без редиректа по-прежнему блокируются.
- **Ссылки из других приложений (`IncomingIntents.kt`, `Tab.kt`, `BrowserScreen.kt`):** если ссылку открыло другое приложение (Custom Tab-запрос с `EXTRA_SESSION` или реферер `android-app://`), вкладка помечается `fromApp`; «назад» с первой страницы закрывает её и уводит наше приложение в фон, то есть возвращает в приложение-источник. Это лёгкая замена Custom Tabs без собственной активности и без `CustomTabsService` (панель Custom Tabs и прогрев не сделаны, но провайдер `CustomTabsService` объявлен: см. раздел «Вход в Google и ссылки из других приложений»).
- **Ссылки в приложениях (`ExternalLinks.kt`, `PrivacyUi.kt`, `Store.kt`, `Tab.kt`, `AndroidManifest.xml`):** обычные http(s)-ссылки по нажатию открываются в установленном приложении, если оно проверенный обработчик этой ссылки (Android 12+, не браузер, не мы). Только при переходе на другой сайт (`sameSite`) и только когда есть `triggerUri`: набранные адреса и переходы внутри сайта не трогаются. Режимы в Настройки -> Конфиденциальность -> «Ссылки в приложениях»: спрашивать (по умолчанию) / всегда / только в браузере (`Store.openInApps`). «Остаться в браузере» догружает страницу здесь. В манифест добавлен `<queries>` для https (видимость пакетов Android 11+).
- **Страница перезагружалась после сворачивания (`Browser.kt`, `Tab.kt`, `Store.kt`, `SettingsScreen.kt`):** при сворачивании все вкладки получали обычный приоритет процесса, и Android убивал процесс страницы первым (затем `recover()` грузил её заново). Теперь текущая вкладка остаётся с `PRIORITY_HIGH` до 20 минут (`KEEP_ALIVE_MS`), потом приоритет сбрасывается. Переключатель: Настройки -> Производительность -> «Держать страницу при сворачивании» (включён). Это снижает, но не отменяет убийство процесса при нехватке памяти.
- **Печать страницы (`PagePrint.kt`, `ToolsSheet.kt`):** пункт «Печать» в меню страницы. Движок сохраняет страницу в PDF (`saveAsPdf`), файл отдаётся системной службе печати Android (принтеры, «Сохранить как PDF»). Временный файл в `cache/print` удаляется после печати и по возрасту (час). Значок пока общий с «PDF».
- **Версия для ПК (`Tab.kt`):** раньше менялся только User-Agent, а раскладка оставалась мобильной (`VIEWPORT_MODE_MOBILE`), поэтому многие сайты выглядели как мобильные. Теперь вместе с UA переключается `VIEWPORT_MODE_DESKTOP` (в `newSession` и в `applyDesktop`): широкий макет, `<meta viewport>` игнорируется. Запоминание по сайту и приватные вкладки работают как раньше.
- **Значок «Печать» (`Icons.kt`):** отдельный значок принтера вместо значка PDF.
- Не проверено сборкой (нет Android SDK). Проверить на устройстве: вход через Google попапом (нужно закрытие окна), `<input type=file>` с `accept=image/*`, с `capture`, `multiple`; вход в приложение с OAuth через браузер.

## Единый дизайн-язык по референсам (Material Player, AovoControl, M3E Canvas) (не выпущено)
Правила: нейтральные карточки одного тона (`surfaceContainerHigh`), один акцент (primary), формы разные по роли: круги (кнопки, значки), очень скруглённые квадраты (плитки, кнопки-квадраты), «печеньки» (заглушки и вкладки), сегментные группы 28/8 с морфингом углов при нажатии.
- `HripsSwitch`: единый обычный переключатель (без галочки).
- Строки настроек, история, закладки: морфинг углов и «вдавливание» при нажатии (`PressSurface`, `Shape.asCorners()`); тон карточек выровнен.
- Настройки: значки в плитках-подложках одного тона (primaryContainer), заголовки секций в акцентном цвете, значение справа в строке (на главной у «Поиск» — текущая система, как «Цвета — Тема Telegram» в плеере).
- Верхняя панель страниц: кнопка «Назад» в круглой подложке (как на экране плеера).
- Печеньки возвращены как заглушки: `ShapeBadge`, пустые состояния, значки типов файлов (одна форма, один тон primaryContainer), превью в контекстном меню, вкладки (кнопка «Новая вкладка», пустая вкладка). Случайные формы в онбординге убраны (везде одна).
- Разноцветные secondary/tertiary заливки заменены на один тон (primary / нейтральные поверхности) (плитки быстрого доступа, типы файлов, пункты меню, значки). Приватный режим оставил в своих оттенках.
- Из M3E Canvas: подтверждение загрузки — соединённая пара кнопок (внешние углы 28, внутренние 8, зазор 3 dp, морф при нажатии); `LoadingIndicator` (морфящийся) вместо круглых спиннеров в расширениях и превью видео.
- Каскадное появление блоков на главной странице настроек (`toolsIn`); индикатор загрузки страницы на планшете/ПК — волнистый.
- Плитка «+» на стартовой с подписью; обои затемняются градиентом; контурные кнопки заменены на tonal; поля ввода — `HripsField`; разовые радиусы заменены токенами.
- Не проверено сборкой (нет Android SDK): при первой сборке смотреть Layout.kt, Expressive.kt, DownloadUi.kt, ContextMenu.kt.

## DownloadUi.kt и DownloadsScreen.kt
- Плашка загрузки: повторное нажатие «Загрузить»/«Готово» больше не принимает файл дважды; плашка не мигает устаревшим содержимым при появлении.

- «Удалить файл» теперь с подтверждением; нет «55 лет назад» при finishedAt = 0; оставшееся время не уходит в минус; убраны неиспользуемые импорты.

## Downloads.kt и DownloadService.kt (не выпущено)
- **Сервис:** остановка по `stopSelf(lastStartId)`, а не `stopSelf()`: если новая загрузка стартовала в тот самый момент, когда сервис решил, что всё скачано, он больше не гасится вместе с ней (загрузка шла без уведомления и без защиты от убийства процесса).
- **Батарея:** `PARTIAL_WAKE_LOCK` держится, только пока что-то качается или стоит в очереди. Пока все загрузки ждут сети, блокировка отпускается (раньше продлевалась каждые 700 мс, пока сеть не появится).
- **Перегрузка пула:** файл без адреса (PDF страницы, снимок экрана), которому не хватило потока, теперь завершается ошибкой «Слишком много загрузок сразу». Раньше он вставал на паузу, продолжить которую нечем.
- **Список загрузок на диск** пишется в фоновом потоке (раньше JSON и запись файла шли в главном каждые 800 мс при изменениях); порядок записей защищён номером, старая версия не затирает новую. Если пул занят, пишется на месте.
- **Восстановление после перезапуска:** одна повреждённая запись больше не лишает списка все остальные.
- Убран неиспользуемый импорт `Toast`.

## ClosedTabs.kt, DefaultBrowser.kt, ContextMenu.kt (не выпущено)
- **«Найти это изображение»** теперь ищет в поисковике по умолчанию (Яндекс, Google Lens, Bing), а не всегда в Яндексе; у поисковиков без поиска по картинке открывается Google Lens, и пункт так и называется (`ImageSearch.byUrl`, `effectiveEngine`).
- **Приватные вкладки:** превью картинки и видео в шапке меню не загружаются (запрос шёл бы мимо изоляции вкладки, как значки сайтов).
- **Возврат вкладки:** `Browser.reopen` не создаёт дубль, если вкладку уже вернули (двойное нажатие по пункту «Недавно закрытые» или «Вернуть»): раньше появлялись две вкладки с одним id.
- «Скопировать изображение»: поток ответа закрывается, если загрузка не удалась или пул занят (раньше соединение висело).
- Список «Недавно закрытые» с ключами элементов; `DefaultBrowser` с константой `VERSION_CODES.Q` и без дубля интента; выровнен код шапки меню.

## BrowserScreen.kt: чистка и исправления (не выпущено)
- **Поиск по фото** вынесен из Compose в `ImageSearch.start`: результаты открываются во вкладке, где нажали (раньше в той, что стала текущей к моменту ответа), закрытая вкладка не получает результат, повторное нажатие во время загрузки не запускает второй поиск, флаг занятости снимается при любой ошибке в фоне.

## Browser.kt и BrowserEngine.kt переписаны (не выпущено)

## Переключатель вкладок: переписан с нуля (не выпущено)
Дизайн прежний, заново написано устройство `TabSwitcher.kt`. Что было не так: карусель на `HorizontalPager` (при закрытии карточки соседние перескакивали), настоящая главная собиралась прямо во время анимации открытия, на карточку приходилось по несколько вложенных слоёв, закрытие ждало хвост пружины.
- **Своя карусель вместо пейджера (`TabCarousel`).** Окно из пяти карточек вокруг камеры. Положение, масштаб, наклон, прозрачность и смахивание задаёт один блок слоя на карточку (`placeWithLayer`), он читает состояние только при рисовании: кадр жеста не вызывает ни перекомпоновку, ни измерение, ни перезапись карточки.
- **Одна камера (`CarouselState.pos`) и один обработчик касаний.** Ось выбирается по первому смещению: горизонталь листает (бросок переносит максимум на одну карточку, доводка пружиной без перелёта), вертикаль на карточке смахивает её.
- **Закрытие без скачков.** Карточка улетает, её место схлопывается за 300 мс, соседи плавно смыкаются, камера остаётся на той же карточке. Закрыли переключатель посреди улёта: вкладка всё равно закрывается.
- **«Закрыть все»:** карточки раздела гаснут разом, потом вкладки закрываются одним шагом.
- **Начальная страница** записывается в общий слой один раз (~0,5 с после открытия, до этого заглушка, потом превью проявляется) и убирается из композиции.
- **Сетка:** один раздел за раз; смена раздела кнопкой или смахиванием по горизонтали; закрытие кнопкой с затуханием.
- **Раскрытие карточки в страницу:** остальное растворяется закраской цвета фона, а не прозрачностью слоя на весь экран.
- **Поиск по вкладкам:** исправлено, список карусели запоминал первый запрос и не обновлялся.
- Без изменений: `captureThumbnail`, шапка, `ModeToggle`, `SwitcherBar`, `ExpandOverlay`, интерфейс `TabSwitcher(browser, onClose, onHistory)`, отложенное закрытие сессий.

2. Смахнуть вверх: порог, значок, возврат пружиной, бросок. Закрыть среднюю, крайнюю, последнюю в разделе, единственную, несколько подряд: ничего не прыгает.

- **Переключатель вкладок переписан с нуля** (`TabSwitcher.kt`): своя карусель вместо `HorizontalPager`, анимации на уровне слоёв без перекомпоновки, плавное смыкание соседей при закрытии, превью главной рисуется один раз, плавная смена «карусель / сетка» (см. раздел ниже).
- **Переключатели (Switch)** без галочки на бегунке: в настройках и в карточке расширения.

## Переключатель вкладок: закрытие не трогает движок (не выпущено)
Причина подвисаний: закрытие вкладки в переключателе шло в главном потоке прямо во время анимации. `Browser.closeTab` закрывал сессию GeckoView и пересчитывал активные сессии, а `BrowserScreen` (читал `browser.current`) перекомпоновывался целиком, переключал `GeckoView` на соседнюю сессию и поднимал отложенную вкладку (`ensureLoaded`).
- **Движок не трогаем, пока переключатель открыт.** `BrowserScreen` запоминает вкладку, которая была текущей в момент открытия, и показывает её под переключателем; `browser.current` в этот момент не читается. Новая текущая вкладка встаёт на место один раз, когда переключатель закрыт (как и при выборе другой карточки).
- **Закрытие сессий отложено.** `closeTab(index, deferEngine = true)` и `closePrivateTabs(deferEngine = true)` только убирают вкладку из списка (и пишут в «закрытые»); сессия закрывается в `Browser.flushPendingClose()`: через 1,2 с после последнего закрытия, когда листание стоит и ни одну карточку не тянут (ожидание не дольше 3 с), при выходе из переключателя, при уходе приложения в фон и перед «Вернуть». «Закрыть все» больше не вызывает `onForeground()` по разу на каждую вкладку.
- **Сохранение состояния вкладок** после закрытия из переключателя откладывается на 2,5 с (раньше через 0,4 с: сбор данных всех вкладок попадал на следующую карточку).
- **Карточка закрывается в момент, когда стала невидимой.** Раньше вкладка закрывалась только когда пружина улёта дойдёт до цели (около полусекунды после исчезновения), и соседние карточки сдвигались с заметной паузой, особенно после броска. Теперь `SwipeState.flyAway` вызывает закрытие, как только прозрачность дошла до нуля; цель улёта ближе (2,6 порога вместо 5). Смахивание и кнопка проходят один и тот же путь.
- **Карусель после закрытия:** если закрыли центральную карточку, последнюю в своём разделе, пейджер переходит к предыдущей карточке этого раздела, а не в приватные (общая карусель оставалась на том же номере).
- Внешний вид и анимации не менялись.

2. Закрыть текущую вкладку и нажать «Готово»: открывается соседняя, закрытая не воскресает; закрыть вкладку с музыкой: звук замолкает не позже, чем через 1,2 с после затишья или при выходе.
3. «Вернуть» после закрытия, «Закрыть все» (обычные и приватные), закрытие последней вкладки.
4. Главная: только логотип и строка поиска, в том числе в превью карточки.

## Переключатель вкладок: переписан ради плавности (не выпущено)
Внешний вид и поведение те же, изменено устройство `TabSwitcher.kt`.
- **Начальная страница в карточках рисуется один раз.** Раньше в каждой карточке с начальной страницей целиком собиралась настоящая главная (сетка плиток, поиск, обои, значки), это было главным тормозом. Теперь один экземпляр записывает картинку в общий `GraphicsLayer`, а карточки лишь копируют её (`HomePreviewSource`, `HomeTabPreview`).
- **Меньше перерисовок.** Списки вкладок, счётчики и группы считаются через `derivedStateOf`: переключатель перерисовывается, только когда результат изменился, а не при каждой смене заголовка или адреса любой вкладки. Карточки получают один стабильный объект `CardEnv` вместо семи лямбд, которые пересоздавались при каждой перерисовке.
- **Кадр жеста ничего не перерисовывает.** Смещение при смахивании, сжатие при нажатии, цвет рамки, прозрачность и наклон соседних карточек, ползунок переключателя читаются только при рисовании.
- **Меньше слоёв на карточку:** смещение, наклон, нажатие, скругление и прозрачность в одном `graphicsLayer` (было четыре вложенных: Box, Surface, clip, graphicsLayer). Подпись снизу и рамка рисуются без `Surface`.
- **Положение карточки не пишется на каждом кадре.** Раньше `onGloballyPositioned` каждой карточки на каждом кадре прокрутки писал прямоугольник в состояние. Теперь координаты хранятся в обычном поле, а `currentCardRect` для анимации страницы обновляется, когда карточка встала на место (после открытия, смены вкладки, остановки прокрутки).
- **Раскрытие карточки в страницу** рисуется одним проходом на холсте (`Canvas`, обрезка по скруглению, `drawImage` с кропом) вместо измерения и разметки `Image` на каждом кадре.
- **Переключатель «Вкладки / Приватные»** без `BoxWithConstraints` (отдельная подкомпозиция): ползунок сдвигается на свою ширину в `graphicsLayer`.
- **Меню карточки** создаётся при первом удержании, а не заранее для каждой карточки. `prepareToDraw` снимка выполняется вне главного потока. Кнопка «+» и нажатия считаются через `Animatable` без перерисовки.

2. Сетка: прокрутка и переключение между «Вкладки» и «Приватные».
3. Смахнуть карточку вверх: порог, наклон, красный значок, возврат пружиной, закрытие броском. Кнопка закрытия и пункт меню удержания закрывают так же.

5. Удержание: меню групп, «В новую группу», «Закрыть вкладку».

  по ETag/Last-Modified) через движок, поэтому cookies и referer те же, что у страницы. Если сервер не поддерживает докачку,
  файл начинается заново, и приложение об этом сообщает. Готовый файл копируется в «Загрузки» (MediaStore).
- **Автовозобновление.** Обрыв сети, зависшее соединение (30 с без данных) и ошибки сервера 5xx переводят загрузку в «Ожидание сети»
  или «Повторная попытка» с нарастающей задержкой (2, 4, 8, 16, 30 с). Как только появляется сеть, загрузка продолжается сама.
  Ошибка засчитывается, только если сеть есть и новых байт нет; после 8 таких подряд загрузка помечается неудавшейся,
  но недокачанная часть остаётся и кнопка «Продолжить» работает. Ссылка протухла (403/404/410) - сразу понятное сообщение.
- **Переживает перезапуск.** Список загрузок (кроме приватных) сохраняется в `files/downloads.json`; после перезапуска
  приложения незавершённые продолжаются сами, приостановленные ждут. Остатки без записи в списке удаляются при старте.
- **Уведомления.** Нажатие на уведомление (идущая, завершённая, ошибка) открывает страницу загрузок внутри браузера.
  В уведомлении кнопки «Пауза» / «Отменить», после паузы остаётся уведомление «Продолжить». Сервис живёт и пока загрузка ждёт сети.
  Когда Android 15 ограничивает foreground-сервис по времени, загрузки ставятся на паузу, а не отменяются.
- **Скорость и стабильность.** Чтение напрямую в файл без промежуточной буферизации (256 КБ), запись без лишних копий,
  обновление интерфейса 4 раза в секунду, `PARTIAL_WAKE_LOCK` пока что-то качается (с выключенным экраном загрузка не замирает),
  поток не занят, пока загрузка ждёт сети.
- **Отдельные страницы.** История и закладки теперь полноэкранные страницы, как загрузки (раньше общая шторка «Библиотека»):
  большой заголовок, поиск, история по дням, удаление записей, очистка истории с подтверждением. «Разрешения сайтов» тоже
  страница вместо шторки. Расширения и настройки уже были страницами.
- Новые значки `Pause` и `Play`; `Library.kt` заменён на `LibraryPages.kt`.

## Что проверить в 0.14.0
1. Скачать большой файл, нажать паузу, подождать, продолжить: счётчик не сбрасывается, файл открывается.
2. Во время загрузки включить авиарежим: статус «Ожидание сети». Выключить: загрузка продолжается сама, без потери байт.
3. Нажать на уведомление о загрузке из шторки (приложение свёрнуто и закрыто смахиванием): открывается страница загрузок.
4. Остановить загрузку крестиком: подтверждение, после него запись «Остановлено» и кнопка «Повторить».
5. История/закладки/разрешения открываются отдельными страницами, «назад» их закрывает.
6. Скачать с сайта, где нужен вход: пауза и продолжение работают (cookies берутся из движка).

## Известные ограничения
- Докачка требует, чтобы сервер понимал `Range`. Одноразовые ссылки и ссылки с истекающей подписью после долгой паузы
  могут ответить 403: тогда нужно скачать заново.
- Файл качается одним соединением (без разбиения на части): для рекордной скорости на быстрых каналах это следующий шаг.
- Загрузки, которые браузер делает сам (PDF страницы, снимок), остановить окончательно можно, а ставить на паузу нельзя.
- Процесс, убитый системой, сам не просыпается: незавершённые загрузки продолжатся при следующем запуске приложения.

## 0.13.0
- **Автоматическая проверка обновлений.** Раз в сутки при запуске (можно выключить) и вручную в Настройки -> О программе.
  Источник: GitHub Releases этого же репозитория. Репозиторий должен быть публичным. Приложение скачивает APK, проверяет пакет и версию и открывает системный установщик (подпись сверяет Android).
- CI после каждой сборки из `main` публикует релиз `build-<номер запуска>` с APK. Для этого у workflow права `contents: write`.
  Обновление ставится поверх только если APK подписан тем же ключом, то есть секреты `KEYSTORE_*` должны быть заданы.
- Адрес репозитория берётся из `GITHUB_REPOSITORY` при сборке (`BuildConfig.UPDATE_REPO`); при локальной сборке обновления выключены.
- Первый запуск: чтобы обновление пришло, нужна ещё одна более новая сборка, чем та, что установлена.

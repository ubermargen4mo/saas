# Изменения

## 0.14.0
- **Загрузки: пауза, продолжение, остановка.** У каждой загрузки кнопки «Приостановить» и «Остановить окончательно»
  (с подтверждением, потому что скачанная часть удаляется). На паузе недокачанный файл остаётся на диске, продолжение идёт
  с того же байта. Сверху страницы есть «Приостановить все» и «Продолжить все».
- **Докачка без потери прогресса.** Данные пишутся в `files/partial/<id>.part`, продолжение идёт запросом `Range` (+ `If-Range`
  по ETag/Last-Modified) через движок, поэтому cookies и referer те же, что у страницы. Если сервер не поддерживает докачку,
  файл начинается заново, и приложение об этом сообщает. Готовый файл копируется в «Загрузки» (MediaStore).
- **Автовозобновление.** Обрыв сети, зависшее соединение (30 с без данных) и ошибки сервера 5xx переводят загрузку в «Ожидание сети»
  или «Повторная попытка» с нарастающей задержкой (2, 4, 8, 16, 30 с). Как только появляется сеть, загрузка продолжается сама.
  Ошибка засчитывается, только если сеть есть и новых байт нет; после 8 таких подряд загрузка помечается неудавшейся,
  но недокачанная часть остаётся и кнопка «Продолжить» работает. Ссылка протухла (403/404/410) - сразу понятное сообщение.
- **Переживает перезапуск.** Список загрузок (кроме приватных) сохраняется в `files/downloads.json`; после перезапуска
  приложения незавершённые продолжаются сами, приостановленные ждут. Остатки без записи в списке удаляются при старте.
- **Уведомления.** Нажатие на уведомление (идущая, завершённая, ошибка) открывает страницу загрузок внутри браузера.
  В уведомлении кнопки «Пауза» / «Отменить», после паузы остаётся уведомление «Продолжить». Сервис живёт и пока загрузка ждёт сети.
  Когда Android 15 ограничивает foreground-сервис по времени, загрузки ставятся на паузу, а не отменяются.
- **Скорость и стабильность.** Чтение напрямую в файл без промежуточной буферизации (256 КБ), запись без лишних копий,
  обновление интерфейса 4 раза в секунду, `PARTIAL_WAKE_LOCK` пока что-то качается (с выключенным экраном загрузка не замирает),
  поток не занят, пока загрузка ждёт сети.
- **Отдельные страницы.** История и закладки теперь полноэкранные страницы, как загрузки (раньше общая шторка «Библиотека»):
  большой заголовок, поиск, история по дням, удаление записей, очистка истории с подтверждением. «Разрешения сайтов» тоже
  страница вместо шторки. Расширения и настройки уже были страницами.
- Новые значки `Pause` и `Play`; `Library.kt` заменён на `LibraryPages.kt`.

## Что проверить в 0.14.0
1. Скачать большой файл, нажать паузу, подождать, продолжить: счётчик не сбрасывается, файл открывается.
2. Во время загрузки включить авиарежим: статус «Ожидание сети». Выключить: загрузка продолжается сама, без потери байт.
3. Нажать на уведомление о загрузке из шторки (приложение свёрнуто и закрыто смахиванием): открывается страница загрузок.
4. Остановить загрузку крестиком: подтверждение, после него запись «Остановлено» и кнопка «Повторить».
5. История/закладки/разрешения открываются отдельными страницами, «назад» их закрывает.
6. Скачать с сайта, где нужен вход: пауза и продолжение работают (cookies берутся из движка).

## Известные ограничения
- Докачка требует, чтобы сервер понимал `Range`. Одноразовые ссылки и ссылки с истекающей подписью после долгой паузы
  могут ответить 403: тогда нужно скачать заново.
- Файл качается одним соединением (без разбиения на части): для рекордной скорости на быстрых каналах это следующий шаг.
- Загрузки, которые браузер делает сам (PDF страницы, снимок), остановить окончательно можно, а ставить на паузу нельзя.
- Процесс, убитый системой, сам не просыпается: незавершённые загрузки продолжатся при следующем запуске приложения.

## 0.13.0
- **Автоматическая проверка обновлений.** Раз в сутки при запуске (можно выключить) и вручную в Настройки -> О программе.
  Источник: GitHub Releases этого же репозитория. Репозиторий должен быть публичным. Приложение скачивает APK, проверяет пакет и версию и открывает системный установщик (подпись сверяет Android).
- CI после каждой сборки из `main` публикует релиз `build-<номер запуска>` с APK. Для этого у workflow права `contents: write`.
  Обновление ставится поверх только если APK подписан тем же ключом, то есть секреты `KEYSTORE_*` должны быть заданы.
- Адрес репозитория берётся из `GITHUB_REPOSITORY` при сборке (`BuildConfig.UPDATE_REPO`); при локальной сборке обновления выключены.
- Первый запуск: чтобы обновление пришло, нужна ещё одна более новая сборка, чем та, что установлена.

## 0.12.0
- **R8 и сжатие ресурсов** включены для release (`isMinifyEnabled`, `isShrinkResources`), правила в `app/proguard-rules.pro`
  (GeckoView и точки входа сохраняются). Если сборка падает или приложение вылетает при старте, первым делом смотрите именно эти правила.
- **Baseline profile** (`app/src/main/baseline-prof.txt` + `profileinstaller`): быстрее холодный старт. Профиль шаблонный, без замеров.
- **Приватность:** в настройках DoH добавлена оговорка, что значки сайтов, картинки превью и проверка адреса DoH идут через системный DNS
  (в приватных вкладках не делаются). Проверка своего DoH-сервера отбрасывает слишком большие ответы.
- **Иконки сайтов:** разбор `<link>` переписан (любой порядок атрибутов, одинарные кавычки, значения без кавычек, `&amp;`, выбор по `sizes`).
- **Поиск по вкладкам:** слова запроса ищутся в любом порядке, в заголовке или адресе.
- **Имена файлов:** обратная косая черта в имени файла тоже заменяется.
- **Тесты:** `app/src/test/.../PureUtilsTest.kt` (имена файлов, поиск по вкладкам, иконки, определение запроса). В CI запускаются после сборки APK и её не блокируют.
- Вынесены чистые функции в `PureUtils.kt` (`sanitizeFileName`, `matchesQuery`, `parseIconLinks`, `resolveIconUrls`).

## Что проверить после обновления
1. Release-сборка проходит с R8; на телефоне открываются сайты, работают скачивание, QR-сканер, расширения (uBlock), видео.
2. Настройки -> Конфиденциальность: текст про системный DNS виден.
3. Иконки на главной и во вкладках появляются.
4. Шаг "Unit tests" в Actions зелёный (если красный, пришлите лог).
